# SciBERT contrastive retrieval for Palestinian-drugs RAG — design spec

**Date:** 2026-04-25
**Author:** wswaileh
**Status:** approved (pending user review of this document)
**Project:** Palestinian-drugs RAG, master's-level deep-learning course paper

---

## 1. Goal & success criteria

The Deep Learning contribution of the project is a SciBERT encoder fine-tuned with contrastive learning on Palestinian-pharmacy-aligned monograph data. Success is defined as:

- The fine-tuned model **statistically significantly** outperforms **all four baselines** (BM25, off-the-shelf SciBERT, BioBERT-MNLI, MiniLM) on **Recall@5** and **MRR@10**.
- Significance: paired bootstrap (1,000 resamples) with 95% confidence intervals; reported per-baseline.
- Two complementary eval sets — auto-mined held-out queries and hand-curated clinical queries — both must show the improvement.
- The ablation table (Type A only / Type B only / both with random negatives / both with ATC hard negatives) is the headline scientific deliverable.

## 2. Inputs (already finalized)

The corpus produced by `build_corpus.py` is the only input:

| File | Contents |
|---|---|
| `corpus/ingredients.parquet` | 1,020 unique active ingredients; 657 with monograph data |
| `corpus/catalog.parquet` | 2,752 catalog drugs |
| `corpus/catalog_ingredient_map.parquet` | 3,060 drug ↔ ingredient links |
| `corpus/chunks.jsonl` | 5,216 RAG-ready chunks ≤150 words, keyed `{ingredient}::{section}::{idx}` |
| `corpus/coverage_report.md` | coverage stats |

Six monograph sections per ingredient: `indications`, `contraindications`, `mechanism`, `drug_interactions`, `side_effects`, `warnings`.

## 3. Train / test split (no leakage)

- **Held-out test set**: 15% of ingredients with monograph data (~98 ingredients), **stratified by ATC level-3 therapeutic class** so common and rare classes are both represented.
- **Train set**: remaining ~559 ingredients with all six sections each.
- **Leakage rule (hard)**: every chunk belonging to a held-out ingredient is excluded from *all* training pairs (anchor, positive, negative). The split is at the ingredient level, not the chunk level.
- **Split file**: `data/splits/train_ingredients.txt`, `data/splits/test_ingredients.txt`. Generated with fixed seed; committed to repo for reproducibility.

## 4. ATC mapping

Anatomical Therapeutic Chemical (ATC) classification is the source of structured "same therapeutic class" labels used both for stratified splitting and for hard-negative sampling.

- **Source**: NLM RxNav REST API (`https://rxnav.nlm.nih.gov/REST/rxclass`) — free, no key. Query each ingredient name → ATC code(s).
- **Fallback**: public ATC CSV from `fabkury/atcd` GitHub repo.
- **Cache**: `data/atc_mapping.json` (ingredient → list of ATC codes). Built once, committed.
- **Coverage acceptance**: ≥85% of training ingredients must map to at least one ATC code. Below that, we expand the alias dict (similar to corpus build) and retry. Ingredients without ATC fall back to **random hard negatives** (degraded, but training continues).

## 5. Training-pair construction

Two complementary triple types, mixed 50/50 in each training epoch:

### Type A — Cross-section self-supervision

| Component | Source |
|---|---|
| Anchor | indications chunk of ingredient X |
| Positive | a chunk from a different section (mechanism / contraindications / side-effects / interactions / warnings) of *the same* ingredient X |
| Hard negative | matching-section chunk from a *same-ATC-class* ingredient Y |

Teaches the encoder that all sections of one ingredient are semantically one entity, and that same-class drugs are not interchangeable.

### Type B — LLM-generated query → ingredient

| Component | Source |
|---|---|
| Anchor | realistic clinical query generated by Claude Haiku 4.5 from ingredient X's indications text (3 queries per ingredient → ~1,700 queries total) |
| Positive | ingredient X's indications chunk |
| Hard negative | indications chunk from a *same-ATC-class* ingredient Y |

Teaches the encoder to map natural-language clinical phrasing onto monograph language.

### Query generation prompt (Claude Haiku 4.5)

For each training ingredient, send Haiku the ingredient name + its indications text and ask for **3 realistic clinical queries** that ingredient should retrieve, with diverse phrasing (symptom-first, patient-population-first, mechanism-first). Output enforced as JSON. Estimated total cost: ~$2 USD.

### In-batch easy negatives

`MultipleNegativesRankingLoss` provides `batch_size − 1` easy negatives per anchor automatically. ATC hard negatives are **concatenated** to the batch (not replacing easy negatives), so effective negative count per anchor = `2 × batch_size − 1`.

## 6. Model, loss, optimization

| Choice | Value |
|---|---|
| Encoder | `allenai/scibert_scivocab_uncased` (110M params) |
| Pooling | mean over token embeddings |
| Framework | `sentence-transformers` 3.x |
| Loss | `MultipleNegativesRankingLoss` (InfoNCE) with explicit ATC hard negatives appended to each batch |
| Optimizer | AdamW, lr 2e-5, weight decay 0.01 |
| Schedule | linear warmup over first 10% of steps, then linear decay to zero |
| Precision | fp16 (T4 supports it) |
| Batch size | 32 |
| Max sequence length | 256 tokens (chunks are ≤150 words → safe) |
| Epochs | 3 |
| Checkpoints | saved per epoch to Drive; resumable on Colab disconnect |
| Total estimated training time | 30–60 min on Colab free T4 |

## 7. Baselines (all evaluated identically)

1. **BM25** (`rank-bm25` library) — lexical lower bound, isolates the contribution of dense retrieval.
2. **Off-the-shelf SciBERT** with mean pooling — the "before" of fine-tuning, isolates the contribution of contrastive learning.
3. **`pritamdeka/BioBERT-mnli-snli-stsb`** — biomedical sentence-transformer trained on STS, strong out-of-domain dense baseline.
4. **`sentence-transformers/all-MiniLM-L6-v2`** — general-domain sanity check.

## 8. Evaluation protocol

### Set 1 — auto-mined held-out queries (~300)

For each of the ~98 held-out ingredients, generate 3 LLM queries using the same Haiku pipeline as Type B. Critically, **the model has never seen any chunks of these ingredients during training**. Each query is labeled with its source ingredient as the gold answer.

Metrics: Recall@1, Recall@5, Recall@10, MRR@10, NDCG@10.

### Set 2 — hand-curated clinical queries (30)

Author writes 30 realistic clinical questions referencing actual conditions, populations, comorbidities. Each query is manually labeled with 1–3 correct ingredients from the corpus. Goal: face-validity check on phrasing the LLM-generated set may underrepresent.

Same metrics as Set 1.

Stored at `eval/hand_curated_queries.jsonl` and committed.

### Statistical testing

For each baseline ↔ fine-tuned comparison:
- Paired bootstrap on per-query Recall@5 and MRR@10 (1,000 resamples).
- Report mean, 95% CI, and p-value.
- Comparison considered "won" if `p < 0.05` AND the lower CI bound of the difference exceeds zero.

## 9. Reproducibility

- Per-epoch checkpoints saved to Google Drive.
- All eval queries + labels committed to the repo.
- Final model uploaded to Hugging Face Hub (or Drive if HF account unavailable).
- `requirements.txt` pinning `sentence-transformers`, `transformers`, `torch`, `rank-bm25`, `faiss-cpu`, `pandas`, `pyarrow`.

## 11. Out of scope (this spec)

The full RAG product (LLM generation + catalog availability join) is built **only as a demo** that consumes the trained retriever. No DL grading attaches to it. Production deployment, query-time logging, and any UI are out of scope.

## 12. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Colab session disconnects mid-training | Per-epoch checkpoint to Drive; resumable training script |
| RxNav coverage <85% | Fall back to fabkury/atcd CSV; below 70% degrade to random hard negatives with explicit note in paper |
| LLM-generated queries are too templated → trivial retrieval | Explicit prompt asking for diverse phrasing; manual spot-check of 30 generated queries before training |
| Improvement vanishes on Set 2 (hand-curated) but holds on Set 1 | Honest reporting; in the paper, position the result as "improvement is partly artifact-driven on synthetic queries"; do not overclaim |
| ATC hard-negative training collapses (representation collapse) | Monitor train/eval loss curves; sentence-transformers' MNRL is stable in practice but watch for it |

## 13. Definition of done

1. All eight ablation rows produced on both eval sets, with bootstrap CIs.
2. Fine-tuned model with ATC hard negatives wins on both Recall@5 and MRR@10 against all four baselines, p<0.05.
3. Reproducibility artifacts (seeds, splits, queries, checkpoints) committed.
4. Final notebook produces the table from a fresh checkout in <30 min on Colab T4.
